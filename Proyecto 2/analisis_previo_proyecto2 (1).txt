------------------------------------------------------------------------
DEPARTAMENTO
------------------------------------------------------------------------
Los 22 departamentos de Guatemala. Casi todos los archivos del proyecto
incluyen el nombre del departamento como texto. En los casos donde no hay
código, el mapeo se hace por nombre contra este catálogo.

  id_departamento     INT  — clave primaria
  nombre_departamento VARCHAR(100)

Fuente: Diccionario de Faltas Judiciales, con los 22 códigos oficiales.

------------------------------------------------------------------------
MUNICIPIO
------------------------------------------------------------------------
Los 340 municipios del país. Se separa de DEPARTAMENTO porque el nombre
del municipio depende de su propio ID, no del departamento al que pertenece
— eso sería una dependencia transitiva y violaría la 3FN.

  id_municipio      INT  — clave primaria
  id_departamento   INT  — FK a DEPARTAMENTO
  nombre_municipio  VARCHAR(100)
  codigo_municipio  INT  — ej: 101  Guatemala capital, 1601  Cobán

Fuente: Diccionario de Faltas Judiciales, municipios 101 al 2217.

------------------------------------------------------------------------
AREA_GEOGRAFICA
------------------------------------------------------------------------
Solo dos valores: Urbana y Rural. Se referencia en MUNICIPIO, PERSONA
y en varias tablas de violencia. Parece trivial pero evitar repetir el
string "Urbana" miles de veces tiene su valor en consistencia y peso.

  id_area      INT
  descripcion  VARCHAR(20)

------------------------------------------------------------------------

GRUPO_ETARIO
------------------------------------------------------------------------
Los rangos de edad usados en los registros. El problema real aquí es que
MSPAS usa una nomenclatura ("< 1 mes", "1a a 4 años") y los archivos de
violencia usan otra ("10a a 14 años", "menores"). Esta tabla unifica todo.

  id_grupo_etario  INT
  descripcion      VARCHAR(50)
  edad_minima      INT
  edad_maxima      INT

EJE 1 — VIOLENCIA


Antes de ver cada subsistema, hay tres catálogos que se comparten entre
varios de ellos:

  CAT_TIPO_FALLO     — usado en Hechos Delictivos, Sentencias y VCM
  CAT_DESPACHO       — usado en Sentencias y VCM

Se documentan dentro del primer subsistema que los define, pero aplican
en todos los que los referencian.

3.1 HECHOS DELICTIVOS
------------------------------------------------------------------------
Fuentes analizadas:
  Hechos delictivos general — 148,537 registros
  INACIF Médico Legal       — 39,968 registros
  INACIF Exhumaciones       — 45,278 registros
  INACIF Necropsias         — 11,038 registros
  Detenidos PNC             — 59,812 registros

Los archivos INACIF traen dos columnas clave: delito_com (el delito
específico) y g_delitos (el grupo al que pertenece). De ahí vienen
TIPO_HECHO_DELICTIVO y GRUPO_DELITO.

  GRUPO_DELITO:
    id_grupo_delito  INT
    nombre           VARCHAR(100)  — Delitos contra la vida, Propiedad...

  TIPO_HECHO_DELICTIVO:
    id_tipo_hecho   INT
    nombre          VARCHAR(100)  — Homicidio, Robo, Asalto... (de delito_com)
    id_grupo_delito INT  — FK a GRUPO_DELITO (de g_delitos)
    codigo_tipo     VARCHAR(20)

Los catálogos complementarios de este subsistema normalizan campos que
de otro modo serían VARCHAR repetitivos en HECHO_DELICTIVO:

  CAT_DIA_SEMANA        — Lunes a Domingo
  CAT_GRUPO_HORA        — Mañana, Tarde, Noche
  CAT_CLASIF_EVALUACION — clasificación de evaluación del hecho
  CAT_INVOLUCRAMIENTO   — tipo de involucramiento del detenido
  CAT_TIPO_FALLO        — Condenatoria, Absolutoria, etc. (catálogo compartido)
  CAT_TIPO_LEY
  CAT_TITULO_LEY        — FK a CAT_TIPO_LEY
  CAT_CAPITULO_LEY      — FK a CAT_TITULO_LEY
  CAT_CAUSA_MUERTE      — solo aplica en necropsias
  CAT_ROL_PERSONA       — Víctima, Agraviado, Sindicado

La jerarquía Tipo -> Título -> Capítulo refleja la estructura real de la
legislación guatemalteca que aparece en los archivos de detenidos PNC.

  HECHO_DELICTIVO:
    id_hecho         INT
    id_municipio     INT  — FK a MUNICIPIO
    id_area          INT  — FK a AREA_GEOGRAFICA
    año              INT
    id_mes           INT  — FK a CAT_MES
    dia              INT
    id_dia_semana    INT  — FK a CAT_DIA_SEMANA
    hora             TIME
    id_grupo_hora    INT  — FK a CAT_GRUPO_HORA
    zona             INT
    id_clasif_eval   INT  — FK a CAT_CLASIF_EVALUACION

  HECHO_DELICTIVO_TIPO_HECHO (tabla puente N:M):
    id_hecho_delictivo_tipo  INT
    id_hecho                 INT  — FK a HECHO_DELICTIVO
    id_tipo_hecho            INT  — FK a TIPO_HECHO_DELICTIVO

Se usa tabla puente porque un mismo hecho puede clasificarse bajo
múltiples tipos (por ejemplo: homicidio + uso de arma de fuego).

  VICTIMA_HECHO:
    id_victima_hecho  INT
    id_hecho          INT  — FK a HECHO_DELICTIVO
    id_persona        INT  — FK a PERSONA
    id_grupo_etario   INT  — FK a GRUPO_ETARIO
    id_rol            INT  — FK a CAT_ROL_PERSONA

  DETENIDO_PNC:
    id_detenido       INT
    id_hecho          INT  — FK a HECHO_DELICTIVO
    id_persona        INT  — FK a PERSONA
    año_registro      INT
    id_mes_registro   INT  — FK a CAT_MES
    id_involucramiento INT  — FK a CAT_INVOLUCRAMIENTO
    id_tipo_fallo     INT  — FK a CAT_TIPO_FALLO
    id_capitulo_ley   INT  — FK a CAT_CAPITULO_LEY

  TIPO_SERVICIO_INACIF:
    id_tipo_servicio  INT
    nombre            VARCHAR(50)  — Médico Legal, Exhumación, Necropsia

  SERVICIO_INACIF:
    id_servicio       INT
    id_tipo_servicio  INT  — FK a TIPO_SERVICIO_INACIF
    id_hecho          INT  — FK a HECHO_DELICTIVO
    id_persona        INT  — FK a PERSONA
    id_municipio      INT  — FK a MUNICIPIO
    año_ingreso       INT
    id_mes_ingreso    INT  — FK a CAT_MES
    dia_ingreso       INT
    id_causa_muerte   INT  — FK a CAT_CAUSA_MUERTE (solo necropsias)

3.2 SENTENCIAS
------------------------------------------------------------------------
Fuente: Excel de sentencias del proyecto + scraping de observatorio.mp.gob.gt

solo aclaracion el observatorio tiene información detallada de
cada sentencia (nombre del sentenciado, pena, etc.), pero no todas las
sentencias del Excel tienen su correspondiente entrada en el observatorio.
Por eso DETALLE_SENTENCIA es opcional — puede existir o no para cada
registro en SENTENCIA.

  CAT_DESPACHO:
    id_despacho  INT
    nombre       VARCHAR(150)

  CAT_FUENTE_SENTENCIA:
    id_fuente_sent  INT
    nombre          VARCHAR(20)  — MP, OJ

  TIPO_DELITO_SENTENCIA:
    id_tipo_delito  INT
    nombre          VARCHAR(200)
    codigo          VARCHAR(20)

  SENTENCIA:
    id_sentencia    INT
    id_tipo_delito  INT  — FK a TIPO_DELITO_SENTENCIA
    id_municipio    INT  — FK a MUNICIPIO
    año             INT
    id_mes          INT  — FK a CAT_MES
    id_tipo_fallo   INT  — FK a CAT_TIPO_FALLO
    id_fuente_sent  INT  — FK a CAT_FUENTE_SENTENCIA
    id_despacho     INT  — FK a CAT_DESPACHO

  DETALLE_SENTENCIA (relación 1:1 opcional con SENTENCIA):
    id_detalle         INT
    id_sentencia       INT  — FK a SENTENCIA
    url_observatorio   VARCHAR(300)
    fecha_sentencia    DATE
    descripcion_caso   TEXT
    delito_text        TEXT  — delito tal como aparece en la fuente
    texto_sentencia    TEXT  — resumen de la pena
    reparacion_text    TEXT  — reparación digna / medidas
    fiscalia_text      TEXT  — fiscalía responsable

  SENTENCIA_PERSONA (puente N:M entre SENTENCIA y PERSONA):
    id_sentencia_persona  INT
    id_sentencia          INT  — FK a SENTENCIA
    id_persona            INT  — FK a PERSONA
    nombre_text           TEXT  — nombre del sentenciado en la fuente

3.9 EMBARAZOS

4. EJE 2 — SALUD PÚBLICA


El eje de salud es más uniforme que el de violencia: los cuatro
subsistemas comparten la misma lógica (municipio + grupo etario + sexo +
año + tipo + cantidad). Por eso se introdujo CASO_SALUD_BASE como tabla
padre que centraliza esos campos comunes.

------------------------------------------------------------------------
4.1 PERÍODO DE SALUD
------------------------------------------------------------------------
En los subsistemas de violencia el año aparece como INT suelto o como
FK a CAT_MES. Para salud se creó un período propio que además registra
la fuente de los datos.

  SALUD_PERIODO:
    id_periodo  INT
    anio        INT  — único
    fuente      VARCHAR(100)  — MSPAS, INACIF, etc.

------------------------------------------------------------------------
4.2 CASO_SALUD_BASE — LA TABLA PADRE DE SALUD
------------------------------------------------------------------------
Todos los casos de salud (desnutrición, enfermedades crónicas, vectores
y morbilidad) comparten: municipio, grupo etario, sexo y período. En vez
de repetir esos cuatro campos en cada tabla, se centralizan aquí.

  CASO_SALUD_BASE:
    id_caso_salud    INT
    id_municipio     INT  — FK a MUNICIPIO
    id_grupo_etario  INT  — FK a GRUPO_ETARIO
    id_sexo          INT  — FK a SEXO
    id_periodo       INT  — FK a SALUD_PERIODO

Cada subsistema de salud agrega sus campos específicos en una tabla hija:

------------------------------------------------------------------------
4.3 DESNUTRICIÓN
------------------------------------------------------------------------
Fuente: 2 archivos CSV (desnutrición aguda + retardo en desarrollo),
19,671 registros cada uno con el mismo formato: municipio, grupo etario,
sexo, año, cantidad.

  TIPO_DESNUTRICION:
    id_tipo_desnutricion  INT
    nombre                VARCHAR(50)  — Desnutrición Aguda, Retardo en el Desarrollo

  CASO_DESNUTRICION:
    id_caso_desnutricion  INT
    id_caso_salud         INT  — FK a CASO_SALUD_BASE
    id_tipo_desnutricion  INT  — FK a TIPO_DESNUTRICION
    cantidad              INT

------------------------------------------------------------------------
4.4 ENFERMEDADES CRÓNICAS
------------------------------------------------------------------------
Fuente: 5 archivos CSV (un año por archivo), 45,437 registros el analizado.
El código CIE-10 y su descripción se centralizan en DIAGNOSTICO_CIE10,
que también usa morbilidad — por eso se mueve a nivel de tablas base.

  DIAGNOSTICO_CIE10:
    id_diagnostico  INT
    codigo_cie10    VARCHAR(20)   — J:45, I:10, E:11...
    nombre          VARCHAR(300)  — Asma, Hipertensión, Diabetes...

  CASO_ENFERMEDAD_CRONICA:
    id_caso_cronica  INT
    id_caso_salud    INT  — FK a CASO_SALUD_BASE
    id_diagnostico   INT  — FK a DIAGNOSTICO_CIE10
    casos            INT

------------------------------------------------------------------------
4.5 ENFERMEDADES TRANSMITIDAS POR VECTORES
------------------------------------------------------------------------
Fuente: 6 archivos CSV (Dengue, Dengue Grave, Malaria, Chagas, Zika,
Chikungunya), aproximadamente 7,060 registros cada uno.

Se agrega CATEGORIA_VECTOR para clasificar las enfermedades: Dengue,
Zika y Chikungunya son arbovirus; Malaria y Chagas son parasitarias.

  CATEGORIA_VECTOR:
    id_categoria  INT
    nombre        VARCHAR(50)  — Arbovirus, Parasitaria, Otro

  TIPO_ENFERMEDAD_VECTOR:
    id_tipo_vector  INT
    nombre          VARCHAR(50)  — Dengue, Dengue Grave, Malaria...
    id_categoria    INT  — FK a CATEGORIA_VECTOR

  CASO_ENFERMEDAD_VECTOR:
    id_caso_vector  INT
    id_caso_salud   INT  — FK a CASO_SALUD_BASE
    id_tipo_vector  INT  — FK a TIPO_ENFERMEDAD_VECTOR
    casos           INT

------------------------------------------------------------------------
4.6 MORBILIDAD MATERNA E INFANTIL (NEONATAL)
------------------------------------------------------------------------
Fuentes:
  Morbilidad Materna   — sin columna de sexo (implícitamente femenino)
  Morbilidad Neonatal  — 181,908 registros, con CIE-10 y sexo

Se unifica materna y neonatal en una sola tabla usando id_tipo_morbilidad.
Para registros maternos, CASO_SALUD_BASE.id_sexo puede ser NULL.

  TIPO_MORBILIDAD:
    id_tipo_morbilidad  INT
    nombre              VARCHAR(30)  — Materna, Neonatal

  CASO_MORBILIDAD:
    id_caso_morbilidad  INT
    id_caso_salud       INT  — FK a CASO_SALUD_BASE
    id_tipo_morbilidad  INT  — FK a TIPO_MORBILIDAD
    casos               INT

  CASO_MORBILIDAD_DIAGNOSTICO (puente N:M):
    id_caso_morb_diag  INT
    id_caso_morbilidad INT  — FK a CASO_MORBILIDAD
    id_diagnostico     INT  — FK a DIAGNOSTICO_CIE10

Se usa tabla puente porque un caso de morbilidad puede asociarse a
múltiples diagnósticos CIE-10.

------------------------------------------------------------------------
4.7 ENLACE SALUD <-> PERSONA
------------------------------------------------------------------------
Los datos de salud son estadísticos (no tienen nombre de persona), pero
para escalabilidad futura se modela un puente genérico:

  CASO_SALUD_PERSONA:
    id_caso_salud_persona  INT
    id_caso_salud          INT  — FK a CASO_SALUD_BASE
    id_persona             INT  — FK a PERSONA

Esto evita crear múltiples tablas puente por subsistema si en el futuro
se dispone de datos individuales.

La mayoría de relaciones en este sistema son 1:N — un catálogo clasifica

  HECHO_VCM <-> TIPO_DELITO_VCM           -> HECHO_VCM_TIPO_DELITO
  HECHO_VIF <-> TIPO_AGRESION_VIF         -> HECHO_VIF_TIPO_AGRESION
  HECHO_DELICTIVO <-> PERSONA             -> VICTIMA_HECHO
  HECHO_VIF <-> PERSONA (víctima)         -> VICTIMA_VIF
  HECHO_VIF <-> PERSONA (agresor)         -> AGRESOR_VIF
  SENTENCIA <-> PERSONA                   -> SENTENCIA_PERSONA
  CASO_MORBILIDAD <-> DIAGNOSTICO_CIE10   -> CASO_MORBILIDAD_DIAGNOSTICO
  CASO_SALUD_BASE <-> PERSONA             -> CASO_SALUD_PERSONA

Relaciones 1:1 opcionales:
  SENTENCIA -> DETALLE_SENTENCIA
    No todas las sentencias del Excel tienen entrada en el observatorio.
  EMBARAZO_UBICACION -> MUNICIPIO
    Solo cuando la ubicación OSAR es de nivel municipal.
  EMBARAZO_UBICACION -> DEPARTAMENTO
